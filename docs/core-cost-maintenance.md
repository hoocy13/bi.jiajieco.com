# 核心成本价维护

清单按商品编号合并商品资料和本地成本版本，展示商品编号、商品名称、品牌、分类、零售价、含税价、核心成本折扣、核心成本价。包含未维护成本及当前库存中已不存在但仍有成本版本的商品。

- 商品资料优先来自 `总库存查询`，只有该表不存在的商品才补充 `分仓库查询`。`含税价`直接读取同名字段，不进行税额换算。
- 同一商品存在多个有效零售价或含税价时显示冲突，不取最大值或平均值。零售价缺失、冲突时，仍可直接维护成本金额。
- 折扣以“折”为单位：`3.5` 或 Excel 中的 `3.5折`表示 35%，不接受将 `0.35` 当作 3.5 折。核心成本价为零售价乘折扣除以十，按 HALF_UP 保留两位小数。
- 旧版本默认直接填价。新版本保存定价方式、折扣、当时的零售价和最终成本；源价格变化后标记基准变化，不自动改成本。历史还原沿用原版本依据和成本金额。
- 批量设置以品牌、分类、关键词定义范围，不限当前分页；状态及成本金额区间不参与范围。默认跳过直接填价商品，可明确选择覆盖。缺价、冲突、计算后非正数的商品跳过，预览显示原因。
- 导出八列，兼容旧四列导入及“货品编号/货品名称”表头。空折扣且空成本不覆盖现值；两者同时填写必须计算一致。折扣基准以当前库存零售价复核，不能通过 Excel 改写 ODS 商品资料。
- 单条保存、导入和批量确认均复核当前成本版本及折扣零售价；先校验全部数据，再写入版本。新版前后端需要一起运行。

管理库启动时以幂等方式补充 `pricing_mode`、`discount`、`base_retail_price`、`barcode` 四列，旧价格及版本不重算。ODS 始终只读。库存估算、销售毛利继续读取已保存的 `price`，沿用当前成本测算口径。部署保留生产管理库，发布代码不导入或覆盖本地成本记录。

验证：`python -m unittest tests.test_inventory_valuation_import tests.test_sales_profit -q`；前端执行 `npm.cmd run build`。

维护状态筛选仅展示全部商品、已维护成本、未维护成本、已删除，页面默认已维护成本。未定价显示“-”。直接填价的商品在折扣列展示核心成本价÷当前零售价×100%的参考折扣，不展示额外标记；缺失或冲突零售价不折算。折算值仅供查看，不保存或导出为定价折扣，避免再次导入改变定价方式。

成本维护列表首列改为库存条码，可按条码、编号、名称搜索。已有成本记录可保存条码用于匹配库存资料；同一条码对应多条库存商品时不自动跨编号匹配。新增最低/最高核心成本折扣筛选，使用百分比原值（包含上下限），例如 80～82 表示 80%～82%，没有有效折扣的商品不进入区间结果；列表整数显示不改变筛选精度。筛选条件同步 URL，导出使用相同区间。2026-10-19 经用户确认，历史编号 LC547900U、F6144300U 分别对应条码 3614272648517、3614274490855；本地修复脚本保留历史价格，停用重复旧编号的有效成本，使用当前编号下已有的相同成本。

维护界面统一以百分比输入折扣：单条与批量输入 25 即 25%，允许 0.01～100，成本预览按零售价×25%计算。历史折扣也展示百分比。API、既有版本和旧版 Excel 的“几折”单位保留兼容，界面在提交前转换（25%对应接口 discount=2.5），不修改已保存成本。
