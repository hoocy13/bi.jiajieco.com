# 预留单分析性能优化

2026-10-21。

生产原接口默认约732ms、13条SQL；每次翻页均执行筛选项、汇总、图表、申请人货品、总数及明细查询。本地曾观测16秒，不能将本地导航等待当作生产接口耗时。

## 实现

- 新增可选 `view=overview|applicants|details|all`，默认 `all` 保持原接口完整返回行为。前端按当前页签传参。总览跳过明细及申请人货品；明细页跳过图表；申请人货品只在下钻到申请人时加载。
- 保留原SQL和绑定参数，按查询结果独立缓存。筛选值、日期、关键词、数据库绑定和SQL均进入键；分页参数仅影响明细查询，所以翻页可复用筛选项、统计和总数。相同键并发合并。
- 每次请求先直接读取单头和明细的更新时间及记录数，作为缓存版本；版本变化即失效。按北京时间日期隔离到期分段，最长TTL60秒。若源数据变更没有推进更新时间且记录数相同，最多60秒后刷新。
- 最多128项，缓存结果序列化体积合计最多8MiB，单项超过1MiB不缓存。返回深拷贝，防止不同请求修改同一结果。
- 申请人和关键词补齐URL持久化；旧请求不得覆盖后发查询结果。

ODS只读，无DDL或源表写入。原申请日期、数量、整单去重、负数及剩余占比口径均保留。原数据更新时间继续展示。
