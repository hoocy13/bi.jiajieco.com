# 经营毛利月度预计算

## 链路及口径

`dwd.销售单明细账_品牌补全` → 独立构建进程 → `ads_monthly_profit_source`、
`ads_monthly_profit_sku` → `ads_publish_batch(dataset=monthly_profit, status=ready)` →
`/api/v1/sales/profit-analysis/monthly-review`。

构建账号写 ADS，源库始终只读；在线账号只读已完成核对的版本。新表的必要 SELECT/INSERT
授权在首次构建前核实，在线账号沿用 ADS 只读权限。本数据集不并入销售或库存版本的清理集合。

预计算保留整单商品覆盖集合、异常标记、订单数及货品汇总，不冻结成本价格或缺成本分类。
在线读取当前有效成本，先重新判定整单是否缺成本，再应用渠道、正装/小样和明细筛选。
维护价格、新增价格、删除或还原成本均改变成本指纹，无需扫描 DWD 即可重新计算。
零金额退货、零金额发货和金额数量方向异常继续按原规则隔离；不把缺成本当作零成本。

商品覆盖匹配保留源 MySQL 排序规则；ADS 中的货号维表保留二进制不同的原货号，
查询时使用源字段排序规则，避免 Python 大小写比较改变整单分类。
金额、数量以十进制字符串保存，聚合使用 Decimal；名称分组保留数据库排序权重和原显示名称。

## 构建、核对与版本

在部署目录的后端容器执行：

```sh
python -m app.jobs.build_monthly_profit_ads --prune
python -m app.jobs.build_monthly_profit_ads --month 2026-08 --prune
```

默认串行构建上海业务日期的本月、上月；指定 `--month` 可重复传参以回填其他历史月份。
每日刷新脚本已在销售毛利 ADS 后追加本任务，沿用现有互斥刷新入口，不并发扫描源事实。
手工更正源视图的金额核实结论或分类规则后，也需重新构建对应月份。

构建使用同一只读可重复读事务，校验源金额、数量、订单数，并与旧查询逐项核对默认、
正装商品、小样缺成本、待核订单视图的完整结果。任何不一致都标记失败，不替换上一 ready 版本。
成本在构建后变化时在线重算，不需要重新发布事实。月份选择及成本日期按上海业务日计算。

负载用字符串池、列式记录和 LZMA 压缩，应用缓存仅保留三份版本；解码兼容首次验证的 gzip 格式。
压缩负载校验 SHA256 及原始字节数。`--repack-only` 可将已有已核对源发布为紧凑格式新版本，
解码后必须与原输入完全一致，不重新扫描源库。原始编码负载限制64MiB。

每个月只清理自身旧版本，至少保留两个 ready 版本。新版本写入源负载、货号维表和 ready 状态
在同一事务提交，读取不会看到半成品。

## 上线与验证边界

首次准备了2026-09、2026-10两个月份。已准备月份响应头为 `X-BI-Query-Mode=ads`，
该路径不执行 ODS/DWD 事实查询；未准备的历史月份暂沿用原查询，响应头明确为
`legacy-unprepared-month`。权限、数据库或校验失败返回503，不通过慢查询隐藏错误。

验证覆盖：成本价格变化、新增/删除成本后的整单分类、默认及组合筛选、待核原因、
只读取 ready 版本、版本切换、压缩精度、货号排序规则、独立保留版本及上海跨月边界。
另外在生产独立进程内模拟改价，没有修改生产成本记录。

性能需要区分首次应用缓存读取、热接口、浏览器页面及历史回退路径；不得把热接口数值当作整页P95。
