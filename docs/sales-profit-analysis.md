# 销售毛利与价格分析

## 页面与权限

页面：`/sales/profit-analysis`。两个分页：毛利分析、客户价格对比。

`sales.profit.view` 默认授予管理层、数据分析师、管理员；导出另需
`data.export`。销售人筛选不是行级权限。普通销售账号不会自动获得全部客户和
核心成本数据。后续自查权限必须先建立账号与稳定业务员标识的绑定。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 销售额 | 明细 `分摊后金额` 净合计，包含退货、红冲 |
| 预估成本 | 已有当前核心成本的 SKU 净销售数量乘核心成本价 |
| 预估毛利 | 有成本部分净销售额减预估成本 |
| 预估毛利率 | 预估毛利除有成本部分净销售额；分母非正时不展示比例 |
| 成本覆盖率 | 有成本的正向销售额占全部正向销售额比例 |
| 成交均价 | 正向成交金额除正向数量；不将净额/净数量当作成交均价 |

核心成本复用库存价格维护的当前版本、删除和恢复规则。缺价不能按零成本处理。
成本价格的生效日期是维护版本日期，不等于商品历史实际采购成本的生效日期。
维护成本后，过往期间的预估结果会按当前成本重新计算。预估毛利不是净利润，
不扣推算的平台费用，也不混用订单头实付金额或库存零售估值。
销售额与核心成本的含税口径尚未核实，结果仅作预估分析。

销售人暂按渠道列表当前 `负责人` 关联，变更负责人会重新归属历史渠道销售。
客户按稳定客户编号识别，优先明细编号，缺失时使用去重订单头编号。
无客户编号或无 SKU 编号的记录仍保留在毛利口径中，不合并成可比较客户。

## 价格基准

比较维度为同品牌、SKU、货品分类、线上/线下及期间；不比较不同商品组合的均价。

- 公司均价：同期间全部销售人已识别客户的正向成交加权价格，保留品牌、商品、分类和渠道条件，
  不受当前销售人、客户筛选限制。
- 本人其他客户：同销售人同期间其他客户加权价格，排除被比较客户自身。
- 上期均价：前一个等长期间的同销售人、同客户、同品牌、同 SKU、同分类、同线上/线下成交价。

价差为成交均价减参考价。正负不代表业务好坏，需结合促销、订单规模、客户条件判断。
低于成本销售额按客户/SKU/具体渠道的正向成交均价判断，不宣称逐笔亏损判断。
参考期不完整或无有效可比成交时，不生成虚假的参考价。

## 数据构建

在线事实查询只读专用 ADS 窄表 `ads_sales_profit_daily`，不在线扫描源销售明细。
源为 `dwd.销售单明细账_品牌补全`，客户元数据由按订单编号去重的
`ods.销售单查询` 补全，仅使用客户编号、名称及有效订单条件，避免无索引的
DWD 订单头产生大范围扫描。销售事实及品牌仍来自 DWD 明细。
每次构建新版本，核对净数量、分摊金额和源行数后才发布为 `ready`；失败保留旧版本。

生产沿用独立 ADS 读写账号。可选 `SALES_PROFIT_DATABASE_URL` 和
`SALES_PROFIT_BUILD_DATABASE_URL` 用于隔离验证；未设置时分别使用现有 ADS 读库和
构建库。构建不得回退使用在线只读账号。

```powershell
cd D:\code\bi.jiajieco.com\backend
.venv\Scripts\python.exe -m app.jobs.build_sales_profit_ads
```

默认构建最近 93 天；也可显式传 `--start-date` 和 `--end-date`。
页面单次查询最多 93 天，并以已发布版本的范围和更新时间为准。
既有 `ops/refresh_sales_ads.sh` 在销售和库存构建后串行刷新此数据集，
成功后使用 `--prune` 只保留自身最近两个已发布版本。
新数据集不能加入 `sales_daily` 的保留版本集合。

本地首次验证使用 `backend/data/sales_profit_preview.db`，只读远程 ODS，
不向线上 ADS 写入数据。实际部署后需首次构建成功，页面才可使用。
