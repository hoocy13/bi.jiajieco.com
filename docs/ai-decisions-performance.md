# 智能洞察加载优化

2026-10-21。

原接口先执行库存和销售查询，再同步等待模型，页面最后只展示模型文案。生产隔离测量跳过模型仍耗时约23秒：库存两条查询合计约35ms，销售日期锚点、当期、上期、渠道四条查询各约5–6秒。

## 当前实现

- `GET /api/v1/ai/inventory-decisions` 只返回业务证据、指标及前20条规则决策，不调用模型。销售复用现有 `sales_daily` 已发布批次，库存保留原只读查询及仓库参数。缓存5分钟、最多32个筛选范围。
- `POST /api/v1/ai/inventory-decisions/summary` 根据服务器保存的证据编号和仓库范围启动模型任务，立即返回状态。客户端不能提交自造业务证据。模型线程创建独立管理库会话。
- `GET /api/v1/ai/inventory-decisions/summary` 只读取任务状态，不重复查业务数据库，也不重新调用模型。继承原 `ai.decision.view` 权限。
- 证据编号包含完整证据、销售批次及仓库范围；内容改变即使用不同编号。同证据的运行中任务去重，完成文案复用；“重新生成”可重做已完成任务。
- 同时最多2个模型请求，最多4个运行或排队任务。证据和文案各保留10分钟、最多64项。过期或范围不匹配返回409，繁忙或模型故障保留指标及规则数据；不回显模型服务异常详情。
- 前端先展示销售指标及规则，再独立更新AI文案。轮询间隔1.5秒、最多120次；切换查询和离开页面后停止旧轮询，并拒绝旧请求覆盖新结果。

仓库筛选仅作用于库存，销售仍为全部销售；页面和模型提示均明确此边界。库存为每日同步快照，查询时间不等于源数据同步时间。销售日期以ADS发布批次为准。ADS未配置或未覆盖完整60天对比周期时明确失败，不悄悄回源慢查询；ODS模式仍支持原查询。

当前生产为单Uvicorn进程，后台任务及缓存保存在进程内。服务重启会丢失任务，客户端重新查询即可；扩展为多进程或多副本前需迁移至共享任务存储。

## 验证

- 先执行回归测试确认原接口会调用模型，再改为业务请求不触发模型。
- 覆盖模型阻塞时立即返回状态、同证据去重、仓库隔离、证据更新、异常脱敏、队列上限、权限、ADS对比周期与汇总。
- 在隔离进程中对比生产ODS与ADS完整销售证据，避免把不同日期或不同业务粒度混用。
- 前端执行 `npm.cmd run build`；后端执行路由与服务编译及相关单元测试。发布后再记录真实HTTP耗时和页面渲染结果。

上线验证：发布任务39567788861成功；默认双仓真实HTTP首次97.0ms，单仓68.6ms，各30次热访问P95为5.5ms、5.3ms。模型启动接口5.3ms返回pending，状态查询4.6ms。原查询与ADS完整销售证据逐字段相等。相关70项回归测试通过；页面实测在AI分析中时已显示4项指标及20条规则，计算样式为4列网格，无横向溢出，控制台无错误。模型文案生成耗时独立于上述数据接口；空响应作为不可用状态处理。

模型补充验证发现推理模型需要额外预算，2000 token可能仅完成推理而无正文。预算增加到4096，要求四节完整、约800至1200字，避免逐条重复证据，轮询窗口覆盖180秒；查询时间使用北京时间。

最终版本 `bbba7eb` 发布任务39568523661成功。复测默认首次191.1ms、单仓63.8ms，30次热访问P95分别5.6ms、5.4ms；任务启动5.5ms，状态查询4.8ms。模型提供方随后返回HTTP 500，隔离线程调用也复现；因此本次未确认最终提示词下完整模型正文生成成功。页面显示明确的模型不可用提示，指标及规则表保留，控制台无错误，北京时间正确。业务数据耗时改善已验证，模型服务可用性是当前外部限制。
