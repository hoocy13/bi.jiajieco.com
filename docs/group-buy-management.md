# 团购管理

页面 `/group-buy`，接口 `/api/v1/group-buy/batches`。

## 权限与存储

- 单一权限 `group_buy.manage` 统一控制查看、编辑、导入、导出、确认、重新开放及批次管理。暂不按品牌、客户或业务人员隔离。
- 复用现有角色权限管理分配此权限；系统管理员启动时具备全部权限。不会自动给其他已有角色增加权限；手动给数据分析师、管理层等角色授权或撤权后，重启服务会保留该团购权限设置。
- 数据位于后台管理数据库的 `group_buy_batches`、`group_buy_changes`。启动通过现有 `init_db` 创建表及权限，不依赖 ODS、ADS 写入。
- 每个批次是有界 JSON 业务文档（最多5000件商品、200个客户列、100个来源），商品排序、筛选在后端进行；工作台通过 `all_rows=true` 一次取得完整商品集合，不展示商品分页。其他API调用仍支持分页。无查询缓存。
- 批次以月份、品牌、名称唯一标识。复制只保留商品属性、价格和列结构，数量全部清零；复制后可修改当期商品属性。
- 顶部“批次管理”按当前月份、品牌列出批次，支持打开、改名、删除和回收站恢复。删除为逻辑删除，保留商品、下单、额度、分配和全部历史；回收站保留同名占用，重复建立时需改名或恢复旧批次。
- 已删除批次不出现在正常列表和复制选项中，不能再查看工作表、导出或修改数量。恢复时保留删除前的编辑/确认状态，不会绕过确认锁定；删除、恢复、改名均校验版本并记录操作者和前后值。

## 数量与商品口径

- 商品为行；左侧固定编码、名称、价格、ABC、PCB及数量汇总。OS表示限定，其他ABC值原样保留，不推断意义。页面列名保留PCB，ABC单元格原样展示OS，不附加“限定”标签；PCB是箱规，未知时留空；箱规不自动改变下单量。
- 商品价格在主表、商品管理和右侧明细中按需显示小数，整数不附加`.00`，有小数时保留实际小数（如12.5、12.35）；金额合计仍保留两位小数。
- 客户分配表仅保留“来源×客户”结构，去掉视图切换和跨来源客户汇总模式；同名客户在不同来源下保持独立列，可直接编辑。旧URL中的mode参数忽略并清除。
- 下单量按商品、柜台记录；分配量按商品、稳定客户列ID记录。相同来源、相同客户的原始重复列各有独立ID，不静默合并。
- 点击商品名称或商品行打开右侧分配明细，可直接修改产品名称并点击“保存名称”；名称修改独立保存，保留尚未保存的分配数量。切换商品、关闭面板及离开页面时提醒未保存名称。数量输入不触发行点击。代码、条形码、价格、ABC、PCB通过面板的“编辑商品资料”或“商品管理”编辑，完整资料弹窗通过“保存商品”保存。汇总格由系统计算，额度通过“维护分配额度”调整。
- “显示列”支持收起商品属性、来源/柜台及单独客户列，产品名称始终保留。属性偏好及各批次列设置保存于当前浏览器；固定列偏移随可见属性重新计算。隐藏不改变批次汇总、分配校验或全批次导出。来源、客户名称完整显示，长名称换行；主表不展示铅笔、三点或重复说明，底部仅显示全批总行数及当前展示行数。
- 表格底部通过“数量合计”“金额合计”两个独立勾选项选择展开，默认全部收起；切换批次或刷新页面后恢复收起状态。展开时固定显示各客户/柜台列的对应合计，金额按当前展示商品的批次价格×对应数量汇总，保留两位小数。商品筛选、数量修改（含尚未保存的输入）后同步更新，横向滚动与列显示设置保持对齐。左侧额度/已分配/剩余也给出对应数量及金额；非汇总属性不相加，未知额度保留“待维护”。金额采用整数分计算，避免浮点累计误差。
- 商品资料中输入产品代码后，离开输入框、按回车或点击“查询商品”，通过 `/api/v1/group-buy/catalog?code=...` 精确查询并带出名称和条码。沿用商品库优先级：先总库存查询，编码不存在再查分仓库查询；ODS仅执行参数化只读查询。保留文本条码的前导零，同编码存在多份名称/条码、资料缺失或未找到时不自动填值。名称和条码默认只读，确需手填需显式开启“手动填写名称 / 条码”；新商品或改编码时未匹配且未开启手动填写不能保存。查询不覆盖价格、ABC、PCB或原批次数据，异步响应校验当前编码以防串值。
- “商品管理”和“客户 / 柜台管理”展示当前批次全部商品、客户列或来源，支持搜索、编辑/改名和删除；表头名称也提供管理入口。客户改名仅作用于该来源下的独立列，来源改名同步两张表的显示并保留稳定ID及全部数量。仅新增下单柜台时客户名称可留空。
- 删除商品同时移除两张表的该商品及其订单、额度和分配；删除客户列只移除该列分配，不改变柜台下单和来源额度；删除来源同时移除其柜台下单、额度和全部客户列。删除前展示影响范围，相关原始数据完整保留在修改记录中，暂不提供商品/列一键恢复。所有操作仅影响当前批次，校验权限、版本及确认锁定。
- 分配额度按商品、来源记录，可设置总额度或追加额度，调整原因必填。下单量变化时，按差额调整柜台额度，保留已经人工调整的部分。
- 商品分配总量包括全部来源。来源、客户筛选只控制右侧显示列，左侧汇总明确保留全来源。商品关键词和差异筛选控制商品集合；列合计使用同一商品集合。页面已移除“限定OS”筛选，旧URL中的only_os不再生效，ABC中的OS原值仍保留。
- 下单表的“柜台已分”只含下单柜台来源，排除吉客云等额外来源。
- 吉客云代表现货，但当前版本不读取实际库存；“合肥上月”等客户/来源名称原样保留，不自动实施跨月结转。
- 导入仅包含分配、缺少下单依据的来源，其有分配商品额度为未知；显示“待维护”。不能用已有分配数量冒充可用库存。
- 确认前逐商品、逐来源核对；存在未知额度或超配时阻止确认。允许留有未分配额度。确认后禁止数量、商品属性、额度和导入修改，需重新开放并留痕。额度提示可用X关闭，关闭仅隐藏提示，不改变额度或确认校验；顶部仅展示数据更新日期。

## 保存与并发

- 数量在界面修改后需点击保存；切换筛选、批次、离开页面前提示未保存修改，多格粘贴同样进入待保存状态。
- 写请求必须携带预期 `revision`；数据库按 `id + revision` 原子更新，数据和审计同事务提交。冲突返回409，前端保留输入并提示刷新核对，禁止继续盲写。
- 历史记录包含操作人、时间、版本、单元格原值/新值；商品属性修改记录前后值，导入记录文件名、SHA256和数量摘要。

## Excel

- 支持本次提供的下单和分配模板：第8行商品表头；下单从G列开始，第3行柜台名；分配从H列开始，第2行来源、第3行客户名。
- 导入走“选择文件 → 检查预览 → 确认导入”，服务器重新解析文件，不信任客户端预览。首次导入建议同时选择两张表。
- 已有商品批次不覆盖导入，避免清除在线维护的内容。需要导入另一份完整版本时新建批次。
- 两表以产品代码匹配，检查商品属性一致性；重复产品代码、缺失来源、负数/小数数量及数量单元格公式会明确报错，不能静默丢弃。
- 导出生成整个批次的下单/分配表，不受当前显示筛选影响；附“分配额度”台账保存人工额度与未知状态。把两份同版本导出文件导入新批次可恢复额度；只导入下单表不会恢复客户分配。
- 数量、价格汇总从明细重新计算，条码和产品代码按文本导出；文本不作为公式或URL执行。不修改用户原始工作簿。
