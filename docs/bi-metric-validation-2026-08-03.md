# BI 全站数据口径验证报告

审计日期：2026-08-03（Asia/Shanghai）

## 技术结论

当前核心销售、库存、到货与周转计算逻辑总体可用，ADS 读取均限定最新 `ready` 的 `data_version`，默认和组合筛选已有自动化测试覆盖。本次确认并修复了三项口径问题：销售分类哨兵值 `-1`、到货 API 默认结束日期、库存成本源为空时错误展示为真实 `0.00`。

总体评级：**可使用，但需带两项运行 caveat**。第一，当前本地环境没有 ADS 连接，无法对生产最新发布版本做实时复算；第二，当前库存源的库存金额和成本价字段全部为零，库存金额类指标必须展示为“暂不可用”，不能用于库存价值决策。

## 页面口径清单

| 页面 | 主事实口径 | 时间字段 | 关键定义 |
|---|---|---|---|
| 经营总览、销售概览 | 订单头实付 | 下单时间 | 排除订单状态含“取消”；订单数只统计货品数量大于 0 的订单编号去重 |
| 销售明细 | 订单头实付 | 下单时间 | 与销售概览保持同一订单头口径，支持状态、渠道、订单关键字分页 |
| 商品排行 | 明细分摊后金额 | 下单时间 | 数量和金额含退货/负数；商品、金额、数量分别按同一筛选集汇总 |
| 品牌销售 | 明细分摊后金额 | 下单时间 | 品牌来自 DWD 补全；正装/小样按货品分类范围拆分 |
| 渠道、品牌渠道 | 明细分摊后金额 | 下单时间 | 有明确线上平台归线上；未配置平台默认线下；未匹配渠道保留 |
| 库存概览 | 当前分仓快照 | 快照更新时间 | 商品按货品编号去重；优先展示可用库存；库存金额不可用时不展示为零 |
| 库存健康 | 当前分仓快照 | 快照更新时间 | 异常按单一优先级分类：负库存、缺条码、不可用、无销量、缺货、超储、正常 |
| 商品周转 | 当前库存与近 30/90 天销量 | 快照更新时间 | 周转天数为库存数量 ÷ 近 30 天日均销量；无销量单独标记 |
| 品牌周转 | 销售 ADS + 当前库存 ADS | 销售日期/库存快照 | 默认上一个完整季度；默认正装、小样和库存不少于 100；未归类品牌排除 |
| 滞销商品 | 当前库存与近 30/90 天销量 | 快照更新时间 | 按 90 天销量、30 天销量升序；红冲不从销售净量剔除 |
| 批次效期 | 批次可用库存 | 当前日期/到期日期 | 仅可用库存大于 0；FEFO 按剩余天数升序 |
| 品牌月度到货 | 入库头与明细 | 实际入库时间 | `docId` 去重入库单、货品编号去重 SKU；负数计入净数量和净成本 |
| 品牌进销存 | DWD 销售 + 日级入库 + 月末库存 | 下单/入库/快照日期 | 期初为起始月上月末，期末为结束月月末；进销存三类筛选一致 |
| 品牌进销存周转 | 销售 ADS + 历史月末库存 | 销售/快照日期 | 平均库存为期间有效月末节点简单平均；周转次数=净销量÷平均库存 |
| AI 决策中心 | 标准销售订单头 + 当前库存/批次 | 最近 30 天/当前快照 | 规则输出与模型证据使用相同仓库筛选；缓存键包含查询模式和仓库 |

## 已修复问题

1. **高：库存金额伪零。** 当库存数量非零而成本金额合计为零时，API 返回 `stock_amount_available=false`，库存概览展示“暂不可用”。
2. **中：销售分类哨兵值。** `货品分类=-1` 的 15,644 行统一归入“未分类”，不再作为真实货品分类暴露；需重建销售 ADS 后生产生效。
3. **低：到货默认日期。** 未传日期时默认范围改为本年 1 月 1 日至当天，不再默认到未来的 12 月 31 日。
4. **低：AI 决策缓存隔离。** 缓存键加入 `BI_QUERY_SOURCE`，防止切换 ADS/ODS 后短时间复用旧模式结果。
5. **低：页面来源说明。** 库存概览、库存健康和 AI 决策页改为标准发布口径说明，避免将 ADS 页面误标成实时 ODS 查询。

## 限制与上线要求

- 当前本地 `.env` 未配置 `ADS_DATABASE_URL`，不能在本机读取生产 ADS 或 `ads_publish_batch`；生产部署前必须在有 ADS 权限的环境执行最新 `ready` 批次复算。
- 当前账号无权读取 `ops.dq_check_result`，质量闸门 27 项结果无法由本次会话独立复核。
- `库存金额` 在源系统补齐前不得用于库存金额排行、超储金额或 AI 金额建议；相关页面应继续以数量和可用库存为主。
- 销售订单头“实付金额”和销售明细“分摊后金额”是不同指标。页面必须保留“订单实付”与“明细净销售额”的命名差异。
- 39 个未匹配渠道应补入 `ods.渠道列表`；在补齐前按业务规则默认线下，不影响线上+线下=总额，但会降低渠道属性分析精度。

## 建议的发布闸门

1. `ads_publish_batch` 最新批次必须为 `ready`，且覆盖页面默认日期范围。
2. 销售 ADS 的订单数、金额、数量与对应 DWD 源汇总差异必须为 0。
3. 库存 ADS 的库存、可用库存、批次和到货汇总必须与 ODS 源一致。
4. 当前库存金额可用率必须显式检查；为 0 时发布允许继续，但页面必须标记金额不可用。
5. 渠道未匹配行数、历史库存缺品牌行数和批次缺效期行数应纳入每日质量监控。
6. 每次新增筛选条件必须同时增加默认条件和组合筛选测试，并更新缓存键。
