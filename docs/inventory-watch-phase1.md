# 库存关注第一期交付说明

日期：2026-11-05。状态：本地开发完成，未提交、未部署生产。

## 入口与操作

本地页面：http://127.0.0.1:5174/inventory/watches 。导航位于“库存分析 → 库存关注”。有 `sales.view` 或 `inventory.view` 权限的登录账号均可使用；配置不按账号隔离。

1. 进入页面先选择已有关注配置的渠道，跳转到该渠道的货品库存列表；没有配置时可通过“配置关注货品”新增。入口不再展示指标卡、多渠道汇总表或大量筛选。
2. 通过“添加关注货品”选择销量参考渠道，可多选。
3. “近30天销售排行”按截至昨天的30个完整自然日的销售数量或金额降序选品；“搜索货品添加”按编号、名称或品牌查找已同步货品，包含近30天没有销售的货品。分类支持多选，选中分类按并集筛选；保留负数退货。
4. 选择添加目标渠道，可以与参考渠道不同。一次最多200个货品、50个渠道、1000个组合；重复组合自动跳过。
5. 渠道库存列表集中展示总库存、可用库存与当前预留数量，保留渠道切换、仓库、关键词、排序和分页；当前渠道及筛选写入 URL。
6. 点击详情，只展示总库存大于0的仓库；预留明细仅保留执行中且当前货品剩余预留大于0的记录。申请、使用开始时间精确到天，使用结束时间在最后一列精确到秒。数量用黑色，其他表内文字浅灰；更新时间统一在详情上方显示，表内不再展示。
7. 公共备注与取消关注放入详情底部折叠的“关注配置”。修改对所有账号生效，保存操作人和审计记录；备注使用版本号防止覆盖其他账号的新修改。
8. 清单增加“我的预留数量”，按当前渠道ID与预留单的渠道对象ID精确匹配，不绑定登录账号。详情在“预留单明细”下方直接展示独立的“我的预留”框，两份明细分别排序、分页，不再使用切换按钮；点击清单上的我的预留数量可定位到该框。多渠道共用预留会计入相关渠道，跨渠道汇总同一笔只算一次，不表示独占库存；缺少渠道ID时显示“—”。
9. 分仓库存默认按可用库存降序，同值按仓库名称排序。“预留单明细”的使用结束时间及列头用黑色，其余非数量文字继续用浅灰色。
10. 更新日期统一放在页面右上角，仅显示到日，删除渠道页副标题。添加抽屉挂载至页面外层，避免被主列表容器裁切；分类多选、数量/金额排行和无销量货品搜索均已进行浏览器与真实接口验证。
11. 详情的分仓库存、全部预留单、我的预留分别使用16像素圆角面板，表格12像素圆角。刷新按钮使用与顶栏相同的圆形刷新图标。添加表格根据抽屉剩余高度和宽度自适应，不再固定420像素高度；窄屏下保留可滚动列表和底部操作区。

首次没有关注记录时显示空状态，不预置业务关注清单。浏览器联调时临时添加的样本已取消；截图中保留的是联调时的样本画面。

## 数据与口径

- 公共配置保存在管理数据库的 `inventory_channel_watches`，唯一键是渠道编号与货品编号，不含用户 ID。`inventory_watch_audits` 保存添加、备注修改和取消操作。
- 模型在 `init_db` 中注册，按现有启动初始化方式创建新表。SQLite 使用 AUTOINCREMENT，避免旧页面持有的已删除 ID 被新配置复用。
- 库存读取最新 ready 的 `inventory_overview` 批次，使用完整的 `ads_inventory_health_item` 汇总数量及商品信息，使用同版本 `ads_inventory_product_warehouse` 提供同步时间。没有使用只保留正库存的周转明细，零库存和负库存保留。
- 库存只按货品、所选仓库聚合一次，不能按关注渠道相加。未在所选仓库快照找到记录时显示“—”，与明确的零库存区分；品牌和分类信息仍保留。
- 近30天销量按北京时间截至昨天的30个完整自然日，从现有渠道货品报表对应的 `dwd.销售单明细账_品牌补全` 只读聚合，按渠道名称和货品编号分组。现有渠道商品 ADS 不含编号，客户商品 ADS 又会排除缺少客户编号的记录，因此没有直接复用它们。
- 配置以渠道编号保存，读取销量时映射到渠道列表当前名称；本次核查没有同名不同编号渠道。后续渠道改名涉及历史销量时需补充历史名称映射。
- 汇总销量仅包含该货品在当前所选且已关注渠道的销量。销量参考渠道与添加目标渠道分别选择，不要求目标渠道近30天有销售。
- 当前预留使用 `预留单查询.状态='执行中'` 且货品明细剩余数量大于0的记录。每笔预留按单号关联，不根据关注渠道猜测预留归属。已过使用结束日但仍有剩余的预留继续展示。
- “3天内到期”和“已过使用结束日”分别检查全部有效预留；同一货品同时存在两类记录时，两种筛选都可以找到它。
- 释放方式展示源字段“到期释放”的规则，不能据此推断某一次实际释放的方式。累计已释放数量也不能解释为本次新增释放或当前可销售数量。
- 所有 ODS、DWD 和 ADS 查询只读。销量聚合复用现有有容量限制的60秒缓存，键包含数据库绑定、月份、渠道集合、货品集合；候选筛选、排序和分页作用于对应聚合结果。关注配置和预留查询不使用该缓存，公共写入后重新读取。
- 全部已同步货品的可选范围是库存快照货品与所选参考渠道近30天销售货品的并集，并非源系统完整商品档案。

## 接口

统一前缀 `/api/v1/inventory-watches`：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /options` | 渠道、品牌、分类和仓库筛选项 |
| `GET` | 公共关注清单、去重概览、分页及各源时间 |
| `GET /candidates` | 按编号选品，包含各渠道近30天销量和已关注渠道 |
| `POST /batch` | 幂等批量添加，事务失败时全部回滚 |
| `PATCH /{id}` | 更新公共备注，版本不符返回409 |
| `DELETE /{id}` | 取消指定关系，重复取消不影响其他关系 |
| `GET /products/{code}` | 所选仓库的分仓库存及预留明细，支持分页排序 |
