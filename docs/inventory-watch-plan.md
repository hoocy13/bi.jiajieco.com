# 渠道库存关注实施计划

日期：2026-11-05。状态：第一期已完成本地开发和验证，尚未部署。实施结果见 [第一期交付说明](inventory-watch-phase1.md)。

## 目标和已确认范围

销售可同时查看多个渠道关注的货品，掌握共享库存、当前预留和到期释放规则。关注配置全员共用，切换账号后可见同一配置。用户不是关注关系的归属维度；账号仅用于鉴权和操作审计。

一期提供查看与配置，不在 BI 中执行源系统预留释放操作。真实释放记录和及时通知在数据能力核实后接入。

## 页面方案

入口建议放在库存分析下，名称“库存关注”，延续 Element Plus 和库存绿色风格。

页面顶部为渠道多选、品牌、货品分类、关键词和预留状态筛选。初次无筛选时查看全部已配置渠道；筛选写入 URL，个人浏览选择不影响公共配置。空清单展示添加引导。

默认“按货品汇总”，同一货品一行，展示关注渠道标签、货品编号、货品名称、品牌、分类、所选渠道上月合计销量、总库存、可用库存、当前剩余预留、最近使用结束日期、到期释放规则和数据更新时间。另一视图为“按渠道查看”，逐渠道展示关注货品及各自上月销量；共享库存明确标识，跨渠道不求和。

混合预留规则的货品显示“多种规则”，通过详情查看各笔预留。使用结束日期标注为到期参考，不能称为实际释放时间；手工释放记录不能承诺到期必然释放。到期提示仅针对仍有有效剩余预留的记录。

货品详情展示分仓库存和预留单明细：单号、状态、预留对象、仓库、申请时间、使用起止日期、释放规则、预留数量、剩余数量、已用数量和累计已释放数量。共享库存不按关注渠道切分；预留对象只有建立可靠映射后才能标为具体渠道。

“添加关注”抽屉支持渠道多选、上月销量选品、搜索全部货品、批量勾选、预览和提交。默认销量降序；各渠道销量可展开查看。明确区分销量参考渠道与添加目标渠道，提交前展示新增的渠道—货品组合数；已存在组合不重复创建。无上月销量的货品也可添加。

表格支持列头排序和后端分页。数量默认整数，金额两位小数。日期筛选保持紧凑，移动端再扩为整行。取消关注明确展示影响的渠道和货品，避免在汇总行上误删其他渠道关系。

## 数据模型

在管理数据库新增公共关注关系表，建议 `inventory_channel_watches`：

- `id`、稳定渠道标识、`product_code`、共享备注、创建/修改时间、创建/修改人。
- 唯一约束为“渠道标识 + 货品编号”，不含用户 ID。
- 渠道标识优先使用可靠的业务编号，开发前核查销售来源与渠道列表能否稳定映射；不能映射时先解决映射，不能把展示名称当成已确认主键。
- 名称、品牌等优先读取商品主数据；失效或已停用货品保留关注关系并提示状态，支持取消。
- 并发批量添加按唯一键去重，返回新增、已存在、失败数量；修改备注需防止静默覆盖。
- 审计保存修改人和操作时间，不将业务关注配置隔离为个人数据。

未来释放跟进另建表，按“渠道 + 货品 + 释放事件”保存共享状态和处理人；事件来源确定前不创建假事件。

## 拟定接口

均使用 `/api/v1/inventory-watches` 前缀，需登录，但不按当前用户筛选关注关系。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /options` | 渠道和商品筛选项 |
| `GET /` | 关注清单，支持多渠道、汇总/渠道视图、排序、分页 |
| `GET /candidates` | 上月销量选品及全商品搜索，返回可靠货品编号和已关注渠道 |
| `POST /batch` | 显式提交渠道—货品组合，幂等批量添加 |
| `PATCH /{id}` | 更新公共备注 |
| `DELETE /{id}` | 删除指定渠道关注关系 |
| `GET /products/{product_code}` | 分仓库存及分页预留明细 |

接口字段和分页格式沿用现有规范。清单响应分别返回销量月份、销量版本、库存版本/更新时间及预留更新时间，不能用一个时间掩盖不同源的新旧差异。缓存包含全部筛选、分页、排序、关注配置版本及源数据版本；共享写入后失效对应缓存。

## 统计口径

1. 上月指北京时间上一个完整自然月；本次规划时即 2026-10-01 至 2026-10-31。销量沿用现有已确认销售口径，保留负数退货，不等同于已发货量。
2. 按货品汇总时，只累计该货品在所选且已关注渠道的上月销量；需要全部所选渠道销量时另行明确标注，不能混用。
3. 库存按货品和指定仓库聚合一次，不能因多条关注关系或多笔预留而放大。库存聚合和预留聚合分别完成后再关联。
4. “当前预留”使用核实后的有效剩余数量，不能用历史累计预留数量。预留、锁定、可用库存之间的关系需对样本核对，不能自行相减推导。
5. 汇总计数按去重货品数统计；渠道视图的行数单独标为关注关系数。
6. 缺少来源记录与真实零库存区分展示。库存与预留快照时间不一致时允许提示差异，不强行对平。

## 开发顺序及验收

### 第一步：解除数据依赖

核查同步运行情况、商品编号粒度销量来源、稳定渠道标识、有效预留状态和默认仓库范围。通过一个同名不同编号商品、多渠道同商品及多仓预留样本完成关联验证。输出字段映射和核对结果。

### 第二步：公共配置和查询接口

新增关注关系模型、初始化/迁移及 CRUD；实现编号粒度候选查询、库存/预留查询及分页。沿用现有销售与库存数据访问方式，ODS 只读，不在在线接口中触发全量同步。

### 第三步：页面和联调

完成清单、两种视图、添加抽屉、货品详情及 URL 筛选。检查真实浏览器渲染和计算样式。第一期不展示没有来源的“最近实际释放时间”。

### 第四步：释放能力增强

核查源系统是否提供逐次释放日志和高频采集能力；有事件来源时展示真实释放，无事件来源时可评估记录快照中的累计已释放增量。增量仅称为“本次同步发现”，发现时间不等于实际释放时间，且需处理首次基线、源数据修正及累计值回退。确认业务需要和成本后再确定采集频率及通知方式。

验收至少覆盖：

- 账号 A 添加后账号 B 可见；账号 B 修改/取消后账号 A 刷新同步。
- 单渠道和多渠道添加、重复提交和并发去重正确。
- 同名不同编号商品不合并；多渠道关注不放大共享库存。
- 默认条件及“多渠道 + 品牌 + 分类 + 仓库”组合查询，汇总、明细、分页统计一致。
- 上月销量按相同日期、渠道、分类和货品编号与来源核对，保留负数。
- 自动、手工、未知规则及混合规则显示正确；逾期不等于已释放。
- 数据缺失、同步滞后和上月销量为零均有清晰状态。
- 后端新增路由执行 py_compile；前端执行生产构建；进行必要的接口测试和浏览器检查。

以上为设计规划；第一期的实际数据来源、实现差异和验证记录以交付说明为准。同步任务和生产环境未在本次开发中修改。
